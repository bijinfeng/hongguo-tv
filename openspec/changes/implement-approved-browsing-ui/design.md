# Design

## Context

动机与范围见 `proposal.md`；全量批次见 `docs/implementation-roadmap.md`。当前 `packages/app/src/index.tsx` 直接创建 store，使用模块级 nav，按 Android OS 决定顶栏；三个入口均 configure HTTP client 后 mount 同一 App。Search 是纵向 List，Detail 固定四列，History 是长文字按钮。Rust 搜索／详情／游客历史可用，播放与账号为未迁移兼容接口。

现有 `packages/ui` 已提供 Button、SearchInput、Surface、Notice、Controls、ResultCard、主题及入场动效。共享应用测试覆盖搜索→详情→播放器、错误／过时响应、历史恢复；library／playback 测试保留裁剪、实际播放前不写记录和完成状态。TV Android 已有 T0 技术宿主与最终 APK 模拟器测试，不能将其当成业务视图验收。

## Goals / Non-Goals

**Goals:**

- 以一组真实业务状态驱动两套视图；端型参数和有限公开组件 API 使开发者及 Agent 能定位修改位置。
- 在不改 HTTP DTO／数据库的前提下迁移已具备能力的设计，保持 legacy 入口与既有测试行为。
- 导航、列表、焦点、输入、错误和动效一起验收；视觉实现依据定稿原型，结果以对应 NSH 宿主观察为准。

**Non-Goals:**

- 不复制原型 DOM／CSS、不创建新的浏览器版产品，不构建通用路由／页面描述语言。
- 不在本批新增 native transport、账号状态机、播放器全屏／评论面板、未迁移发现 API 或历史管理写操作。它们在后续切片按完整功能台账实现。
- 不因浅深截图、headless 或模拟器通过而声明物理电视、硬解、Windows/Linux 或正式发行通过。

## Decisions

### 1. 明确端型装配，双端视图留在 app 包

应用接受最小 `desktop | tv` 产品端型（暂定命名，实施时服从已有 API）；Web/Desktop 显式传 desktop，TV 显式传 tv。legacy 脚本复用 `apps/web`，不再维护根级 demo 入口。业务 store 和查询／续播动作复用；可在 `packages/app/src` 内为 desktop/tv 分组视图，按实际文件增长拆分，不复制 store。

不以 `platform.os === 'android'` 推导 TV；OS 仅用于确有需要的宿主差异。不一次性引入完整 AppServices／native adapter 框架，因为本批只有现成 HTTP transport。后续 C 批接原生时再按实际接口提取。

### 2. 根拥有导航和来源，页面拥有草稿／滚动

调整现有路由以区分一级目的地和详情／播放器子流程。导航保留 drama ID、来源目标、列表锚点／焦点 ID 与详情选集段；页面可保留挂载或恢复局部状态，避免每次切一级导航重复初始化请求。把导航与 store 生命周期绑定到应用根，防止新增双端壳造成模块级残留或重挂载串状态。

不向持久历史写导航位置，不在本批建立全局持久页面仓库。返回由最上层流程持有；旧 Player、Account 对导航的引用随必要接口变化更新，不能留下两套 nav。

### 3. 先建立共享控件的端型尺寸与状态

扩展 `packages/ui` 的有限 `variant/size` 与必要内容槽，保留原公共导出或同时迁移全部调用方。页面只组合 UI 与布局，颜色、圆角、字号、间距和动效归共享基础。需补 cinema 配对前景、错误／禁用等语义角色时先改主题；不把原型 CSS 作为第二个 token 来源。

仅添加本批导航、海报、选集、状态提示与必要弹层使用的控件；在内部测试预览中验证代表控件，避免先生成未消费的完整组件库。定稿中的 CSS px 需映射为 NSH 逻辑单位并用 TV density 320 实际观察，不能直接认定是 dp/sp。

### 4. 搜索和选集保持稳定身份

保留 domain ID 作为 List key／testID，页级保存当前项身份和位置。NSH List 回收单元中的 props／signals 只在绑定读取，行内不持有会串到其他剧目的业务状态。海报、网格／内容行采用各端 `.nsh/types` 已支持的结构；先验证代表集合的回收与焦点后再铺页面。

详情以现有 episodes 切段：桌面每段最多 24、TV 最多 12；列数按端型和可用宽度适配。续播集不在首段时选中对应区间；保存集缺失／锁定提供明确选择，不将旧时间套给其他集。不造分季模型或把缺失筛选映射为本地假排序。

搜索仍使用现有首批 HTTP 查询；明确更多结果边界。分页接口与 UI 追加在 D 批统一接入，避免本批悄悄改变匿名搜索／App 游标语义。保留失败前快照与输入，旧请求隔离使用现有 resource 取消机制并增加行为回归。

### 5. 首页只组合真实可用数据

首页续播来自同一 library 资源；桌面紧凑条目、TV 内容展示区由同一记录派生。无历史时自然显示找剧主动作，不展示原型推荐海报、虚假统计或成排未实现栏目。历史条目仍经过详情检查后恢复播放，不绕过锁定、媒体来源限制和现有会话策略。

新增导航名称和首页仅表达已有能力；后续栏目在协议／UI 同时可用后加入。完整首期目标保留在台账中，避免阶段 UI 可用性与最终范围混淆。

### 6. 现有播放／账号是兼容边界

本批可改变进入／返回的装配，不重写 Player 的媒体会话或 Account 的认证请求；保持旧 HTTP／legacy 行为回归。Rust 501 继续作为服务错误提供重试与返回，不通过演示视频填补。

任何组件共享变更同步检查 Player、Account、T0Probe 与旧入口。播放测试保留“无实际播放不保存”“切集／后台保存”“完成不被退出覆盖”。完整双端播放器、面板、显隐、定位与全屏行为由 B 批负责，避免重复做一次模拟播放器。

### 7. 动效与宿主证据分开维护

下列是本批待实现清单；在页面编码前写入根 DESIGN.md，并用固定 NSH API 核实工具。不是已通过记录。

| 状态变化                       | 工具／共享 token                                            | 减少动态效果               |
| ------------------------------ | ----------------------------------------------------------- | -------------------------- |
| 控件 hover／pressed、选中变化  | 颜色 transition，fast 100ms；焦点即时，几何稳定             | 即时换色                   |
| 主内容首次进入／错误提示出现   | 现有 entrance，180ms ease-out、8 逻辑单位；不逐回收单元重播 | 无位移，即时可见           |
| 导航切换                       | NSH 导航语义／共享转场，不叠加双重页面动画                  | 即时恢复内容与焦点         |
| 选集段变化、续播文字／历史刷新 | 原位即时更新，避免阅读跳动                                  | 相同                       |
| 加载、列表滚动／回收           | 有限静态占位／文字，原生滚动；无无限装饰动画                | 相同                       |
| 拖拽、播放器实时值、评论弹层   | 本批无新增；保留现有播放器反馈                              | 沿用现有策略，另记未验证项 |

完成时在真实宿主逐项检查圆角、字号、间距、对齐、颜色、hover／pressed、状态和动效，浅深两种外观均记录。TV 明确空间导航、输入出口、IME、列表回收及返回；现有 T0 instrumentation 需要增加业务测试路径或独立业务测试，不能只复跑技术按钮就勾选。

## Risks / Trade-offs

- [两套布局造成业务漂移] → store／请求／续播共用，测试相同业务不变量；仅视图和输入职责分端。
- [导航生命周期调整影响旧入口和播放保存] → 所有 nav 调用点一起迁移，三端及 legacy 共享回归，稳定测试 ID。
- [原型尺度不能直接用于 NSH／TV] → 控件与代表页面先在实际宿主验证，禁止靠未知类名通过静态推断。
- [首批首页没有完整推荐] → 使用真实续播和搜索；完整功能保持后续批次与台账，不放假数据。
- [全屏测试打断用户工作] → 本批不改完整全屏设计；后续专门验收窗口执行，不自动启动 Chrome／全屏。
- [安全门禁与跨平台限制仍未解决] → 状态单列，第一批跟进；不降低策略，不把 UI 验收视为发行许可。

## Migration Plan

1. 建完整功能台账，修正文档过时起点；记录修改前行为和本批动效映射。
2. 扩展共享主题／控件并验证代表组合，再接最小端型与根导航，保持现有页面可达。
3. 依次迁移搜索、详情、历史与首页，逐步替换旧页面组合；每步保留可运行状态。
4. 扩展共享与端型测试，完成 check/build、完整 verify 及宿主观察，追加真实验证结果。
5. 本批不改数据库／协议；回退以整批恢复原壳与页面组合，不触碰 `.local/data/`，不删除既有历史。无需双存储、双写或并行产品入口。
