## Goals / Non-Goals

**Goals:**

- 让基础控件的外观／输入契约在UI层解决，业务组件只组合真实数据与动作，页面只组织完整任务。
- 每一层都有明确输入、状态所有者、稳定选择器、状态样板和验收出口，避免只在最终页面发现问题。
- 先完成共同基础，再还原页面；保留三端共享业务及桌面／Web的现有表现。

**Non-Goals:**

- 实施不引入DOM运行时、React／Vite、全局Android density改写、第二套搜索／片库／播放器控制器。
- 原型的播放、账号、日期、排名和个人记录不构成新接口、有效登录凭据、评分或统计。

## Decisions

### 1. 沿用三层组件边界，主题位于基础层之下

依赖顺序为：`DESIGN token → packages/ui基础组件 → packages/app业务组件 → packages/app页面／外壳`。业务数据由既有store／controller通过core-client进入；ui不读取store，不请求接口，不持久化业务状态。`apps/tv/App.tsx`继续只负责mount和宿主能力注入。

| 层         | 拥有                                             | 输入／输出                                       | 不能拥有                                 |
| ---------- | ------------------------------------------------ | ------------------------------------------------ | ---------------------------------------- |
| 基础组件   | 字级、尺寸、图标、焦点、状态皮肤、通用输入／浮层 | 受控值、有限variant／size、语义事件、ref、testID | 目录请求、账号同步、导航路由、观看记录   |
| 业务组件   | 列表分组、数据投影、来源、局部草稿及业务动作组合 | 真实数据／状态、active、动作回调及来源恢复       | 第二份已提交片库、第二个播放器或云写队列 |
| 页面／外壳 | 页面结构、主任务、路由、布局配置及生命周期接入   | store／controller与宿主能力                      | 重新画基础控件、逐页覆盖字体／颜色／边框 |

保持一个公共UI包。基础控件不读取`ProductTarget`来自行决定业务；端型差异由app选择布局与显式输入模式，几何从对应主题取得。UI包内可以拆文件，产品仍从包根导入，内部不反向导入barrel。

不采用“每页直接翻译HTML”的做法：那会把原型的全局对象、CSS和演示Set变成第二个产品实现。也不采用“每一个div都是组件”：普通排列继续使用View／Scroll／List，仅真实重复组合或独立语义形成组件。

### 2. 先映射token，避免TV样式通过公共主题污染桌面

DESIGN继续是唯一可编辑的生产视觉源，`pnpm design:codegen`生成两端主题与字级关系。实施时增加可选`colors-tv`、`rounded-tv`覆盖块：只覆盖已知语义键，未覆盖键继承公共定义；未知键／非法值必须报错。字级、controls及spacing继续复用现有分端机制，不再增加第二个token生成器。

这两个块已接入生成器，覆盖键与合法值由回归约束。生成器回归必须证明：没有TV覆盖时输出与原规则一致，TV覆盖只改变TV文件，桌面／Web既有键和值不变；浏览器组件主题同步仍由既有工具负责。候选CSS在实施前仍独立保存，不能手改生成theme来凑截图。

视觉数值与用途统一引用[设计说明的尺寸契约](../../../docs/design/tv-redesign.md#尺寸与组件契约)，此处不复制数值表。实现映射：文字归现有语义角色及TV字级，普通控件归controls档位，导航归独立语义token，颜色／圆角归TV覆盖，安全区与集合密度归下节布局派生。修改视觉值只改设计来源，再通过生成链映射到生产主题。

普通按钮、主播放和导航分别用明确档位／语义组合。保留现有Button API；新增NavigationItem承接“当前目的地”的字级与状态，内部复用现有按键／焦点行为根，不复制Button控制器。不把`fontSize`、颜色、圆角作为页面可随意覆盖的参数。

### 3. 原生布局使用points，不复制浏览器整树缩放

已在TV生成类型核对：`windowSize()`返回surface的points，`pixelRatio()`是每点设备像素数，`fontScale()`是用户文字倍率；`ViewRef.measure`说明几何测量不包含transform。因此不把浏览器的`transform: scale()`直接套在NSH根节点，也不从面板3840宽再次重算一遍字体／density。

以960×540作为设计基线，生产按宿主points和局部可用区域布局。实现的第一批用现有TV预览入口记录`windowSize`、`pixelRatio`、`fontScale`、系统insets及onLayout实测结果；核对720p／1080p场景是否落在预期逻辑尺度，4K场景记录真实UI画布。该步骤验证已选单位模型，不新增原生适配库；如宿主违反该单位契约，先定位宿主问题，不靠全局transform补偿后继续页面迁移。

新增app内`src/shell/tv-layout.ts`，集中从真实points、fontScale及主题布局值派生内容宽度、密度档位、列数和安全边距。它不保存目录／账号状态；在响应式绑定中读取环境，不在模块加载或组件body取一次快照。基础控件只保留单一系统文字缩放：字级token是基础值，fontScale仅参与容器／减列计算，不再乘进Text字号。

字号阈值与各集合列数统一引用[文字与布局适配表](../../../docs/design/tv-redesign.md#文字与布局分别适配)，不在技术方案维护第二张表。

设计表给出基线档位，局部宽度不足时还要按最小可读项宽减列，不能在侧栏内容区强塞六列。优先使容器增长、操作换行和局部滚动；控制栏和海报图片不按字体倍率整体放大。浏览器100%～200%的审阅选项不是本次新增的生产设置项；现有外观设置没有自定义字号偏好，本批使用系统字号。

TV系统安全区与overscan只有一个拥有者：TV根的SafeFrame按两者的较大值，再预留焦点余量；共享App根在TV分支不重复应用同一系统insets，桌面／Web原逻辑保留。背景和媒体可铺满，重要操作与文字进入安全内容区。非16:9先保留设计比例的内容区域／留边，不拉伸视频或裁掉操作。

优先保留现有`pages/home`、`pages/player`、`pages/account`、`pages/settings`。只在两个页面确实共享时提升到`packages/app/src/components/<domain>/`，不引入新的全局状态库或万能页面配置引擎。

| 业务组合             | 拟落点／现有基础                                                     | 主要契约与状态所有者                                                                  |
| -------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 首页重点／目录／续播 | 保留pages/home的HomeHero、CatalogSection、ContinueSection            | 真实feed／history派生显示；主要播放与详情动作回到store                                |
| 自适应内容集合       | 扩展现有PosterCollection                                             | 明确grid／shelf布局；接收items、active、caption和source回调；复用现有锚点／focusGuard |
| 搜索工作区           | pages/search，复用SearchForm                                         | 查询与最近搜索仍归现有controller；连接RemoteKeyboard、输入、联想和结果，不复制请求    |
| 详情内容／选集浏览   | pages/detail及必要的components/episodes                              | 详情、当前浏览季、分段、locked／upcoming由既有状态决定；仅精确可播对象触发播放        |

| 榜单／日历           | 保留rankings子组件、Calendar控制器                                   | 保留完整服务选择树、真实日期、分页、来源及演员目标；布局改变不改变参数语义            |
| 设置／维护           | 保留pages/settings各模块                                             | 同一设置读写与更新流程，包含并行诊断项；诊断仍默认关闭并受真实能力约束                |

组件输入通过受控props／信号或既有窄controller端口传递，输出是明确意图；不在可回收行中建立membership／分页／登录状态。NSH组件只运行一次，props、行item和环境在绑定中读取；资源与effect清理跟随既有owner。

### 6. 虚拟化和焦点是业务集合的一部分

PosterCollection继续作为唯一集合实现，增加grid／shelf呈现选项；按当前列数组行并使用真实实体身份。不再给TV传入桌面四列公式计算的卡宽，也不再将固定138点横向项当作所有TV页面。

返回顺序为：找到精确实体 → 按当前列数算目标行／恢复有效offset → 等待该行存在 → 在focusGuard仍有效时恢复焦点。文字倍率或宽度改变时按ID重定位；offset需夹在有效区域内，不能只保存旧行号。演员／剧集同ID仍按`kind:id`区分。删除后复用既有移除焦点交接，来源消失回退到下一个有效项或页主入口。

大列表用原生List；有界选集按区段构建，长范围条局部滚动。页面、键盘、结果、播放面板分别拥有自己的滚动区域，不给List外面再套同轴Scroll。搜索输入保留在左栏滚动区之外，键盘／历史只滚其内容；右侧结果独立List，滚动指示器在本区边缘。

### 7. 导航是TV投影，不能削弱现有业务

主入口固定为精选、找剧、榜单、我的。搜索／设置为唯一顶部工具入口，账号摘要合并头像与身份；去掉常驻遥控说明、额外账号按钮和时钟，详情／账号／设置使用次级页头，播放器独立全屏。

保留现有NavStack和来源Map，在app层添加所需TV导航状态：根section新增我的；搜索、日历、片库集合和信息页可使用受类型约束的子route保存来源。内部仍使用现有`rankings`等业务身份，不为了展示标签重命名DTO、持久键或原测试ID。组件样板只走开发入口，不成为产品路由。

统一更新页面active判定：新子route可激活相应现有controller；TV四个根页面之外，不同时挂载旧隐藏浏览页和同一集合的新内容。隐藏页保留必要草稿／滚动，但移出焦点、读屏候选并取消其不再拥有的请求；详情返回不能重新建store／丢分页。桌面Browse与已有入口语义保持。

### 8. 视觉还原服从真实能力

- 新网格仍保留服务提供的short／comic、分类／排序、榜单树和分页。不能把原型五个固定分类或三个榜别当作完整服务目录。
- 榜位只显示明确rank；原型按数组index生成的序号不能复制到正式榜单。缺字段时保留无编号卡片，不由热度推算评分。
- 遥控字母键盘只编辑现有query；中文仍使用已有IME。是否可提示“拼音首字母”需真实接口证据，不增加本地音译协议。
- 收藏／追更／预约／清空按既有提交结果反馈；pending／失败保留原状态与重试，不抄原型直接改Set的成功路径。
- 清晰度、全屏、二维码、支持资产和安装按真实能力显示；NSH Storage偏好与Rust片库等当前所有者保持，不趁UI调整迁移持久状态。
- `add-diagnostics-reporting`等并行改动在接线前复核，布局迁移保留同一开关、能力与默认关闭规则，不因设计稿无该行而删除。

### 9. 每层先验收，页面还原最后组装

| 层         | 验收产物                              | 通过条件                                                                   |
| ---------- | ------------------------------------- | -------------------------------------------------------------------------- |
| 规范／主题 | TV token映射及生成快照                | TV独立输出正确，Desktop／Web默认输出不变，图标共源                         |
| 基础组件   | 扩展现有BaseComponentsPreview／UI预览 | 同一生产组件覆盖语义状态、浅深、大字、确认／返回与焦点，不是重新手绘的样板 |
| 业务组件   | 既有场景入口的组合fixture             | ID／回收／异步取消／pending／失败与来源正确；合成通过仅计边界回归          |
| 页面       | 同任务同数据的v4与NSH对照             | 字级、几何、对齐、图片、信息层级、单一焦点和无冗余入口逐项核对             |
| 正式流程   | 真实入口＋真实数据＋实际宿主          | 搜索／详情／播放／返回、管理、账号、偏好等逐项记录来源、平台、源码和限制   |

实现批次按影响运行三端check和build、相关UI／app测试；主题／图标分别运行design:check、ui:icons:check，DTO或依赖实际变化才额外执行相应生成／安全检查。最终执行pnpm verify，不能降低旧门禁或把TV已有skip消失当作修复。

验收矩阵包括标准／保守安全区，浅深主题，100%／130%／200%文字，720p／1080p输出与可用4K场景，长剧名、图片失败、1000集、长选择树、回收后返回、焦点项删除、IME与减少动效。4K面板不等于4K UI画布。MVP 的 TV 验收宿主是固定 API34 AVD 模拟器，其注入的遥控、IME 与焦点矩阵即验收依据；headless 不替代该模拟器或原生读屏，物理电视、硬解与真实 4K 输出按平台限制记录。

关键选择器复用`nav-home`、`nav-discover`、`nav-rank`、`nav-search`、`nav-settings`、`drama-<id>`等，新增Mine／集合时使用业务ID命名；已有ID语义不变。Agent通过真实控件的role／label／testID操作，预览选择器不进入产品；不增加只供截图使用的交互分支。

## Risks / Trade-offs

- [TV token改动波及Desktop／Web] → 覆盖块带默认回退，快照验证桌面输出不变；共享组件只加有默认值的有限契约。
- [全局缩放导致焦点／popup／媒体坐标不一致] → 使用NSH points、原生布局与模态；先验证宿主单位，不复制DOM寻焦或整树transform。
- [减列使虚拟化行身份变化] → ID＋有效offset重算行，保留focusGuard／异步发布权限；专项验证切字号、删除、分页和返回。
- [新增Mine／子route导致双挂载或请求失活] → 显式active映射、单一controller、TV根页面列表与桌面分开组成，不复制业务实现。
- [原型缺少真实功能或示例字段误入生产] → 页面映射包含既有扩展；继续使用真实DTO／台账，修改两条旧布局规范时保留所有身份和数据约束。
- [同时重构组件与页面导致回归难归因] → 下列批次逐层交付；共享API兼容，先通过组件样板再接业务和页面。
- [代码仍在并行变化] → 实施开始重新记录dirty文件、活跃变更和相关接口；本规划不是对旧源码快照的强制覆盖。

## Migration Plan

批次、前置关系、交付与验证出口统一维护在[tasks.md](tasks.md)。按其编号顺序逐批推进：原生度量完成后进入基础层，再进入业务组合与页面还原；组件预览和真实流程分别验收。此处不复制第二份批次表。

每批是可评审、可单独回退的变更集，不要求提前造独立PR或自动提交。回退仅恢复该批拥有的主题／组件／接线，保留现有持久数据和其他并行改动；没有数据库迁移需要倒回。旧受控API／页面接线在对应批次稳定后再清理，避免长期保留两套产品路由；开发预览保留为同源验收入口。

不先承诺固定人天。P0／P1以原生度量、弹层与主题生成验证工作量后，再按已确定批次估时；每一批的功能、来源和验收出口已经明确，不将“重新调研整个仓库”留给实施阶段。
