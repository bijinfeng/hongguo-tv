# 本机账号会话

`AccountService::open(directory, guest)` 接受宿主明确的数据目录与游客 `LibraryStore`，拒绝把账号库注入为游客库。HTTP/native 共用该协调器；它管理单一本机活动账号，不是公网多用户会话管理器。当前提供官网 QR、手机号／验证码及额外短信验证的协议与本地状态机；恢复本机会话不代表远端凭据仍有效。

成功登录的凭证保存在应用私有目录；正常关闭仅排空会话，不执行退出，下次使用同一目录启动时恢复账号。只有用户明确退出才清除当前凭证；远端过期或撤销仍可能要求重新登录。验收复用正式入口的私有目录，不复制凭证到测试目录，也不在流程结束时自动退出账号。

## 状态与切换

`Account` 只公开身份、`owner_epoch` 和安全的登录展示状态，凭据不进入 DTO。账号命令必须携带最新快照的 `owner_id`、`owner_epoch`；两者是前置条件，不是任意账号选择器。启动与每次成功提交重新生成 epoch，A→B→A 的旧命令仍会被拒绝。QR／手机号推进另需精确 attempt ID；取消、替换、过期和丢弃尚未提交的网络请求都会使旧 attempt 失效。错误阶段的调用不会取消当前可编辑 attempt。

切换持有协调器锁，先封存并排空旧库和目标库的写会话及已接纳 worker，再原子保存凭据，最后发布新账号、epoch 与库。已接纳的提交与手机号注册设备保存由独立任务继续持锁，设备写入不含账号凭据；caller 取消或响应丢失不撤销提交，通过 `state()` 同时重读账号与历史核对结果。保存失败保留旧 owner 与凭据；已封存的写 token 不重新开放，客户端需重新申请。客户端仍须丢弃旧 scope／操作的迟到响应。

退出只清除当前凭据并切回原游客库，保留各账号的本机历史与收藏；不会把账号数据迁入游客库，也不会替游客启动云同步。观看历史库与写屏障见[存储约定](../library/README.md)。

## 云同步与游客导入

`open`、`clone` 和 UI 读取不会暗中启动网络任务。HTTP/native 宿主每个服务实例只显式启动一次 `run_sync(shutdown)`，退出宿主前先同步调用 `stop_sync()` 再发送 shutdown 并等待 worker。第二个 worker 返回 Busy；已停止或被丢弃的实例不能重启。账号恢复后的首轮可能上传既有 outbox 与首次对账候选，真实账号验收必须在启动前取得该范围授权。

单 worker 采用 2 秒合并窗口、90 秒周期和 3 分钟整轮截止。轮次捕获 owner、epoch 与取消代次，先完整 pull/merge，再逐项上传并精确 ACK，全部排空后保存私有刷新凭据与成功时间。网络期间不占账号协调锁，本机注册写入继续可用；历史上传的任一双写失败、ACK／凭据／时间保存失败均保留安全错误，不能报告整轮成功。凭据不进入 Account DTO、错误或日志。

切号、退出、同步停止及整轮超时会拒绝后续过期步骤与迟到的内存状态／凭据发布。已经接纳的 SQLite 操作持有协调锁排空，可能完成其事务；取消不代表回滚，远端已接收的部分双写也不会被虚构撤销。native 关闭在后台等待这些步骤、当前账号库和游客写队列排空；同一目录及其别名重开先等待旧会话释放生命周期锁，首次尚不存在的目录也保持同一身份。优雅关闭等待这些已接纳步骤；直接丢弃 worker future 会立即停止后续步骤，稍后的 `state()` 或切号仍等待存储排空。

显式 Sync 只唤醒已启动的 worker 并返回当前权威状态，不提前返回同步成功；缺 worker 返回 NotImplemented，游客与过期 scope 被拒绝。成功的注册写入在调用方丢失响应后仍会唤醒 worker，失败回执不会触发同步。`state()` 同时对账账号、历史、收藏、待同步数量和真实游客候选；游客快照或候选查询失败不制造零，也不复用旧候选数。

`ImportGuestHistory` 必须显式调用，先等待已接纳的账号／游客 checkpoint，再保持原播放时间导入合法且较新的进度，只生成账号待同步操作，不导入游客收藏，也不修改游客库。watermark 使响应丢失后的重传不会重复导入；队列空间不足时返回真实 imported/remaining，释放空间后可重试剩余项；完全无法接纳时返回 `LIBRARY_SYNC_QUEUE_FULL`，不会把队满伪装成存储未准备。导入与账号切换都持有同一 scope 屏障；取消调用方不撤销已接纳的导入，使用 `state()` 和候选数核对后重试。

## 存储

| 路径                     | 内容                                                 |
| ------------------------ | ---------------------------------------------------- |
| `account.sqlite3`        | 当前身份与私有凭据，以及剥离账号凭据后的注册设备信息 |
| `guest.sqlite3`          | 原游客历史                                           |
| `accounts/<uid>.sqlite3` | 固定绑定该 UID 的本地历史                            |

会话库 `application_id=0x48474143`、`user_version=1`，单行保存；payload／device 各限 128 KiB。SQLite 使用 `synchronous=FULL`、`secure_delete=ON`、DELETE journal；阻塞操作在 `spawn_blocking` 中串行执行。Unix 新目录 0700、会话文件 0600，拒绝非普通会话文件；这不是系统钥匙串或数据库加密实现。只初始化空库，不导入 legacy 数据；损坏、未知版本和身份／凭据 UID 不一致均拒绝恢复并保留原文件。

旧 `apply_history` 没有 generation，只在服务启动后尚未切换过的游客状态兼容。账号状态及本次服务内任何成功切换后，即使已退出，也返回 `SessionExpired`；正式客户端始终使用注册写会话。

## 验证边界

`cargo test --locked -p hongguo-core` 包括合成协议响应、真实 loopback 传输、临时 SQLite、attempt 失效、A→B→A、并发 checkpoint、双写／精确 ACK、超时／关闭、部分导入与存储故障回归。它们不能证明真实登录、短信投递或远端 MFA 可用。正式 Desktop 已观察真实扫码登录、同库重启恢复及退出清除凭据；账号观看记录隔离和其他平台／手机验证仍待验，见[当前验收](../../../../VALIDATION.md)。本批离线回归不计为真实账号的云拉取、云写入、跨设备冲突、收藏同步或游客导入验收。
