## 当前起点

内容发现、详情／系列、Rust 播放及原生装配已有大量实现，但不少项目只有合成边界或部分真实流程证据，不能统一标记完成。账号迁移、同步、收藏／追更／预约、统计及维护／跨平台交付仍有明确缺口，逐项状态以台账为准。

原生 bridge／Desktop mixed／TV 独立业务的 C3.3 工程收尾已完成：完整 verify、契约生成检查和 OpenSpec strict 均通过。2026-11-20 按精确版本补齐 `deny.toml` 例外后，根工作区 `pnpm security` 也通过；`v0.1.0` 随后按该门禁正式发布（run 44688698633）。但两条 unmaintained advisory 无修复版本、生成宿主锁文件不在根图内，供应链证据仍未补齐，见[依赖检查](dependencies/native-release-security.md)。C3.2 的 macOS Desktop mixed 真实观看／重启／焦点验收因锁屏保持开放，不能由 headless 或 TV 证据替代。

游客历史管理 E1 尚未整体验收。当前播放器修复已本地交付并有最终工程检查；真实 Web 流程曾在后段详情超时，Desktop native 曾返回 `409 / PLAYBACK_IDENTITY_MISMATCH`，封面加载、完整焦点／后台、当前 TV 包等还有未通过或未验项。后续一次原生日志诊断实际恢复播放，但不解释旧409、不作为整体验收；具体结果统一见VALIDATION。主会话已进入账号／会话／owner隔离批次，本路线不重复维护运行细节。

此前真实 Web／TV 成功证据保留其源码、平台和范围；新失败也保留。安全依赖、物理电视、Windows／Linux、公开 Web 隔离、正式签名升级等开放项不能被工程通过或旧包验收覆盖。

### 条件触发项

TV 宿主保持 Java 17。`apps/tv/android` 只是薄胶水层（`MainActivity`、`TvRemote`、`UpdateInstaller`、`UpdateResultReceiver`），业务在 NSH TSX + Rust；`android.useAndroidX=false` 下 Kotlin 的扩展函数与属性委托不可用，收益只剩语法糖。迁移代价覆盖 1050 行主源码、1181 行 `androidTest` 和 `tooling/fixtures/*-tv` 三套 overlay 工程，并需固定 Kotlin 插件版本、重生成 `gradle/verification-metadata.xml` 校验和、接入格式／静态检查门禁后重跑 TV 三套 overlay 与 CI。仅当 `TvRemote` 需要结构性改动（焦点模型重构、新控件种类），或节点遍历的显式判空开始反复引发缺陷时，才把整个 app module 一次性迁到 Kotlin，不保留 `.java` 混合。

### 并行边界

主会话负责集成、契约边界和当前队列；有可独立交付的任务时再分配实施者。可并行账号核心、既定契约下的界面、独立设置／许可能力或真实验收；不要把全部并行额度用于重复调查和重复审查。

每个任务写明负责路径、输入契约、交付物、受影响平台与退出条件。DTO／状态所有者先由一个负责人定稿；共享入口、台账和验证记录由集成者汇总。不得并行覆盖同一文件，或在契约未定时各造一套实现。

共享 Cargo／NSH 输出、图形宿主、模拟器、账号会话及全量验证由一个执行者串行使用；其他人继续独立编码或只读审查。复用已确认缓存，临时目录只存缓存／可再生产物，交付源码留在主工作区。

## 每批怎样执行

1. **固定交付边界。** 在相关 OpenSpec 中用一小段明确用户流程、平台、范围外事项、接口／状态所有者、定向命令、真实验收和 UI 审查条件。复用已有变更，不为每个小修复新建一套文档。给本批工作量预估；遇到新阻塞时更新预估和队列，不虚报 MVP 完成时间。
2. **先接真实能力，再扩展界面。** 核对上游和真实响应，尽早从正式入口走通代表流程；产品实现与必要边界回归同步推进，不先铺大量假页面和合成状态再找真实数据。
3. **开发中运行定向检查。** 按改动层运行 Rust／状态／控件／宿主回归。NSH 界面改动必须 check 和 build；DTO 改动执行 codegen 与 codegen:check；依赖变化执行 security。使用已有命令，只有缺少可重复验证入口时才补最小工具，不为一次运行建设通用框架。
4. **冻结本批代码再做完整门禁。** 集成完成并审查后，由一人运行一次完整 `pnpm verify`；正在编辑的文件不作为本批稳定输入。新发现修复后先做定向验证，再按影响决定重跑范围；本批交付源码必须有适用的完整门禁依据。不能一边持续改产品一边反复启动全量检查。
5. **真实流程和 UI 双审。** 正式入口使用当前真实服务／实际播放形成的数据，完成本批流程；界面在实际宿主观察还原度、完整度和输入／返回行为。独立审查覆盖功能与界面，依据证据给结论；headless、核心 probe、截图或合成宿主不能互相代替。
6. **交付并进入下一批。** 汇总变更、真实流程／合成边界／工程检查的各自结果、未解决项和下一步。按既有授权作聚焦本地提交，保留不相关改动；不因局部通过关闭整个变更或 MVP，不擅自推送、归档或发布。

真实验收涉及账号写入、短信或外部副作用时遵守已有明确授权；缺授权只阻塞相应步骤，不虚构成功或让其余独立开发全部停住。

### 失败与证据复用

- 将长流程拆为可独立复现的用户任务，记录各段结果和失败点；后段失败不抹掉已证明的局部事实，也不能把整条链记为通过。重启／同步／跨模块连续性仍需最终端到端验收。
- 证据关联源码身份（含相关未提交文件）、入口／包、数据来源、平台、时间及步骤。源码与依赖范围未变的证据可以复用；DTO、共享状态、控件、宿主、配置或上游语义变化后检查受影响消费者，不把过期证据算到新版本。
- 失败先分类为产品、上游／数据、环境或验收工具问题。有新假设／修复／环境变化才针对性复验；不在相同条件下整套反复重跑取绿灯。网络重试遵循真实产品行为并保留原始失败。
- 单一故障持续无新信息时，交接明确错误、最小复现、已排除因素、下一步和负责模块；继续无依赖的队列。不得通过放宽身份校验、安全门禁、等待断言或改用合成数据关闭故障。
- 状态区分“待核对／待实现／已实现待真实验收／已验收／平台不适用”；另记工程检查和阻塞原因。任务勾选数、测试数量和 OpenSpec 格式通过不表示功能完成率。

| 当前规则       | 产品、架构、工程、设计与长期能力 spec            | 直接维护有效条款；重要决策附原因或链接归档，不混入每日操作日志                   |

### 本轮收敛与后续边界

本轮已完成：统一[文档导航](README.md)、README运行入口与[手册](development.md)分工、稳定架构及两项[ADR](architecture/adr/)、VALIDATION当前矩阵／失败索引、台账去除日期增量、单一组件覆盖矩阵及历史迁移。AGENTS改为按任务阅读，旧正文与失败在[历史索引](history/README.md)保留；产品源码和OpenSpec任务未因此改变。

OpenSpec 生命周期已在 2026-11-20 单独收口：21 个任务全完的变更逐个核对 delta 后归档到 `changes/archive/2026-11-20-*`，并生成 20 份主规范（`openspec validate --specs` 20/20 通过）。其中 `wire-approved-feed-ui` 的 `recommendation-browsing` 因用户已取消独立刷剧页面，没有写入主规范，只归档保留历史 delta；匿名推荐核心的 `anonymous-recommendation-feed` 仍保留。归档只表示该变更的交付范围结束，不表示其功能已通过真实流程验收——状态仍以台账和 VALIDATION 为准。

其余 11 个变更仍有未完成任务，保持开放，不打断主会话正在实施的账号批次。它们的能力路径与已归档主规范不重叠；但同一功能可同时有存储层与界面层能力（例如已归档的 `guest-history` 定义记录存储，开放中的 `continue-watching` 定义共享 UI 展示），这类并存是分层而非重复。13 个变更的 delta 只有 `ADDED` 要求，因此后续归档可直接新建对应主规范，不需要修改已有要求。

文档管理采用产品／长期行为规范／架构决策／变更方案与任务／验收证据分层。保留既有PRODUCT和根规范路径，不再建立重复PRD；PRD不复制API或状态机，单次技术方案归OpenSpec design，重要决策才建ADR，替代时标记Superseded。包／crate／fixture与技能资料就近保留，由索引导航，不机械搬迁所有Markdown。

整理前根必读资料约20.4万字符，约69%来自验收日志；本轮将完整日志和历次设计审查移到历史，Agent默认读取概览与任务相关规范。一个事实只在其责任文件维护，其他文档链接，不再复制组件说明或逐次进度。

## 主会话继续入口

先读取本路线、台账相关行、VALIDATION当前相关失败及账号活跃变更，继续账号／会话与隔离批次，并按资源与路径边界并行推进可交付模块；不因文档整理重复已完成的播放器检查／诊断。E1、真实原生播放及其他未验项继续有负责人和后续步骤，不以“继续账号”替代解决。

每次交接只报告：**本批交付、真实验收结果、工程检查、阻塞及下一批**。无需重新阅读全部历史或重新证明未受影响的基础链路；完整 MVP 最终仍按全部范围验收。
