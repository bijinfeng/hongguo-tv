日期：2026-11-14。状态：A 已实施，桌面系统字体缩放仍待验；B4c 已接通 TV 生产页面的 DPAD／媒体键与逐层焦点，Web 官网观看／重启续播保留 B4b 证据；C1／C2 已完成原生 transport、mixed 注册、默认生产入口和显式预览装配，原生包已构建，TV 原生官网观看／后台／重启续播已在三组模拟器外观验收；macOS 输入、全屏及独立业务尚未验收。用户已授权分批本地提交；不推送或归档。

## 目标与起点

首期目标仍为 `PRODUCT.md` 中的完整功能对齐。Web／桌面和 Android TV 采用已确定的两套界面，共享业务、数据契约和记录规则；TV 独立组织页面、焦点和播放操作，不采用桌面放大布局。

设计依据为 [原型规格](design/prototype-system.md)、[页面地图](design/ui-map.md)、[桌面修复](design/desktop-review-fixes.md) 和 [TV 修复](design/tv-review-fixes.md)。`design/prototype/` 是交互参考，演示数据、DOM 实现及模拟成功状态不进入生产。`DESIGN.md` 顶部 A 批映射记录当前实现，下方保留迁移前快照。不能把定稿等同于已通过 NSH 宿主验收。

## 第一批的明确边界

先实现可用页面及必要导航结构：首页只展示真实续播与找剧入口；Web／桌面保留侧栏、搜索和内容工作区，TV 保留独立顶部结构、内容行与搜索页。推荐、排行榜、追剧、下载等页面按后续批次接入，不生成假列表或可点击死入口。此为实现状态安排，不删除已确定的首期功能。

本批不重写播放／账号协议、不引入 native adapter、不扩展持久状态、不改变数据库；原有播放器与账号入口保留，错误由现有请求真实反馈。原型的桌面 24 集／TV 12 集分段可以基于已有详情数据落地；分季、筛选和下一页搜索等缺失能力不造字段或伪造成功。

先完成 UI 基础与代表页面，再按搜索→详情→历史／首页顺序迁移。页面状态、焦点、来源与滚动归 TSX；真实历史仍归 Rust。各端薄入口只注入明确端型，业务和双端视图都在 `packages/app`，不往 `apps/tv` 复制业务。

## 功能台账与完成定义

第一批先创建一份逐项台账，覆盖 `PRODUCT.md` 与 `docs/design/ui-map.md` 的所有行。每项记录固定上游源码／行为指针、目标批次、受影响端、协议／契约、状态所有者、回归选择器、证据和缺口；状态区分“待核对、待实现、已实现待宿主、已验收、平台不适用”。不以入口存在或 mock 成功记为完成。

每个切片同时改善三项体验：用户完成真实任务并能恢复；开发者通过现有命令复现；Agent 根据有限公开接口、稳定 ID、状态所有权和失败证据继续工作。避免额外说明标签、通用页面配置引擎和未使用控件。

## 验证与交接

- 实施前核对当前 Git／并行修改与工具状态；首次环境按 README 安装及 setup，运行 doctor，缺工具明确失败。保留现有 staged 内容，不自动提交、推送或归档。
- NSH API 查各端生成 `.nsh/types`；每次 UI 改动运行对应 check **和** build、必要行为测试，批次结束运行完整 `pnpm verify`。Rust DTO 改动执行 codegen 并提交 OpenAPI／generated.ts，再 codegen:check；依赖变动执行 security。
- UI 在实际 Web／桌面宿主和 TV 模拟器观察，记录视口、主题、字体缩放、减少动态效果、输入／焦点／返回与逐项动效结果；headless 与截图不能互替。遵守先前“不打断工作”的约定，不自动启动原生 Chrome 或进入全屏；需要全屏验证时留到专门验收窗口。
- TV 完整业务不得借 T0 技术页验收过关。现有 `pnpm test:tv-emulator` 面向 T0；业务流程需要扩展对应装配与宿主用例后再声称覆盖。物理遥控、硬解、厂商兼容和长播独立列证据。
- 安全基线仍有 NSH 间接依赖许可证及停止维护阻塞；按依赖责任分别处理，不能降低门禁或仅凭 verify 通过标记可合入／发行。Windows／Linux、真实账号、公开 Web、正式签名与升级未验证项继续保留。
- `VALIDATION.md` 只追加本次实际运行结果；每批交接写明变更、命令／结果、证据、未验证项及下一步。产物／凭据／运行配置保持忽略。
