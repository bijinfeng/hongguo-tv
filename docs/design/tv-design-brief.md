# Android TV 独立设计简报

用户已确认：TV 与 Web／桌面采用独立的设计思路。TV 从客厅观看、远距离阅读和遥控输入出发设计，不以桌面页面的响应式断点或放大模式交付。

状态：独立页面方案已落实为可点击浏览器原型。顶部主导航为精选、找剧、追剧、我的；播放器、页面组合和样式均与桌面分开。当前可审阅方案与检查边界见 [原型规格](prototype-system.md)，尚未作为 NSH 真机通过的证据。

2026-11-13 独立复审后，已实现输入出口、播放进度隔离、返回路由、共享排序和评论滚动五项修复，并将找剧筛选收敛为三个选择框。修复记录见 [tv-review-fixes.md](tv-review-fixes.md)；新布局和真实遥控／输入法仍未完成宿主验收。

## 设计出发点

- 内容和观看优先。首页帮助用户接着看或选择下一部；管理、输入和配置按任务进入。
- 焦点是主要操作指示。每个页面先定义方向键路径、默认焦点、区域切换和返回，再确定视觉布局。
- 播放是独立的全屏体验。控制层、进度定位、选集、评论和错误恢复围绕遥控操作组织，不沿用桌面播放器加右栏的结构。
- 竖屏短剧保留比例；画面两侧如何承载信息、何时退场，需要在 TV 播放方案中单独审阅。
- 保留完整功能。评论、搜索、账号和管理的输入成本通过专门流程解决，不因 TV 输入不便而删掉功能；手机辅助可作为补充，不作为默认必需条件。

## 独立交付内容

| 设计对象   | 需要明确的结果                                                         |
| ---------- | ---------------------------------------------------------------------- |
| 信息架构   | TV 页面地图、主导航、栏目层级；顶部导航与侧栏按实际遥控路径选择        |
| 首页与浏览 | 续播、发现和内容行的组合；焦点信息区；长列表分页与行位置记忆           |
| 找剧与搜索 | 分类浏览、搜索输入、结果选择和返回；避免桌面筛选栏直接搬用             |
| 详情与选集 | 简介阅读、播放／续播、系列与季、大量集数定位和不可播放状态             |
| 播放器     | 遥控键位、控制层显隐、进度预览与提交、换集／换剧、全屏内面板及逐层返回 |
| 我的片库   | 续播、收藏、点赞、追更、预约、下载与管理的 TV 组织方式                 |
| 账号与互动 | 扫码及原有登录分支、评论输入、草稿保留、账号隔离与同步失败恢复         |
| 系统与设置 | 媒体键、电视首页入口、后台恢复、偏好、诊断及维护流程                   |
| 状态规范   | 焦点／选中／播放中分离，加载、空、失败、禁用、超长文案及面板焦点恢复   |

## 与 Web／桌面的共享边界

共享内容模型、搜索与筛选含义、剧集和系列关系、账号状态、记录及进度规则、播放业务命令，以及可适用的品牌语义 token。

页面组合、导航、密度、字号尺度、焦点机制、面板和播控分别设计；控件是否复用由交互是否一致决定。业务仍归 packages/app，端型视图在共享业务之上明确分开；控件和主题归 packages/ui，各端入口保持薄层。独立设计不等于复制一套业务或扩大端入口职责。

## 审阅与验收

先独立审阅 TV 页面地图，再审首页、详情／选集、播放器与返回流程，最后补齐完整功能和异常状态。Web／桌面方案通过不代表 TV 通过。

原型阶段演示遥控流程；最终用真实 TV 宿主、遥控器和媒体播放验证观看距离、焦点、返回、媒体键、解码及后台恢复。浏览器方向键模拟不能替代这些证据。
