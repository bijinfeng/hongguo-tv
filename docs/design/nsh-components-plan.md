# NSH 基础组件与视觉方案

日期：2026-11-14。状态：基础组件已授权实施。本文为设计与边界依据，实际API／使用规范见 [UI包](../../packages/ui/README.md)，还原与完整度证据见 [实施验收](component-implementation.md)。沿用已确认的桌面／TV设计与安静观看范围。

后续高频基础的详细用途、状态、焦点路径与 NSH 映射见 [组件预先设计与演进](component-roadmap.md)。八类新增浏览器样板共用状态与控制器；布局直接组合 View，原生公共导出随真实消费逐步落地。

## 1. 方向

建立项目自己的轻量 UI 层：**NSH 提供基础能力和交互行为，`packages/ui` 提供统一风格，`packages/app` 组合业务。** 沿用暖白、深绿灰、红色主动作和 Lucide 线性图标，以封面和视频为视觉中心。控件清楚、克制，避免装饰性卡片、重复说明和多种同等醒目的主按钮。

**一份组件行为与状态契约，两端分别呈现。** 不建立 DesktopButton／TvButton 两套控件；字号、目标尺寸、间距、焦点轮廓和面板宽度由集中端型档位决定。Web／桌面键鼠和 TV 遥控输入在边界适配，提交、取消、禁用、等待、错误与来源恢复仍复用同一控制逻辑。产品不增加手机／窄窗布局，不增加评论、弹幕、剧评、点赞或无依据的离线任务。组件能力不能反向创造业务需求。

## 2. NSH 怎么用

| 层             | 使用方式                                                                                  | 责任                                                                 |
| -------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `nsh`          | `View`、`Text`、`Image`、`List`、`Scroll`、信号与动效等                                   | 渲染、布局、资源、响应式与宿主基础能力                               |
| `nsh/base`     | `Button`、`Input`、`Select`、`Switch`、`Checkbox`、`Slider`、`Tabs`、`Dialog`、`Sheet` 等 | 按压、控件角色、选值、焦点、键盘、弹层关闭等基础行为；不预设项目外观 |
| `packages/ui`  | 项目控件、主题、尺寸、图标、焦点适配与状态样式                                            | 对页面提供有限、稳定、带风格的公共接口                               |
| `packages/app` | 页面、表单、剧目身份、接口状态与流程组合                                                  | 业务意义、数据加载、导航、确认与恢复                                 |
| `apps/*`       | 注入明确的 `desktop`／`tv` 端型与宿主能力                                                 | 薄入口，不各自制作组件库                                             |

本方案已对照 NSH 0.5.0 生成类型；没有假设 React、DOM、CSS 选择器覆盖或 npm UI 组件可直接用于 NSH。导航根继续使用 `NavStack`／`NavPage`，普通布局可直接使用 `View`／`Text`／`List`，不为改名封装每个原语。普通控件的 `nsh/base` 装配和样式收敛到 UI 层。

使用原则：组件函数只运行一次，props 和信号在 JSX 绑定或闭包中读取；值由调用方控制，控件报告变化，不在控件里发请求或写持久状态。API 以每端 `.nsh/types/` 为准，不从其他框架类推。

需要明确的接口边界：

- Base Button 没有 `variant`／`size`／`loading`；这是项目 UI 层拟提供的语义，不能直接传给 base。现有焦点回调由项目适配处理，也不能假设 Base Button 有 `onFocus/onBlur`。
- Base Tabs 不使用 `value/onValueChange`，由每个 Tab 的 `selected/onPress` 表达；方向键自动选择与异步页面加载要配合，不能把未读完的数据当作已切换完成。
- Dialog 的内容外观使用 `class/style`，Sheet／Popover 的弹出内容使用 `popupClass/popupStyle`；各组件保留自身语义，不能做一个万能浮层替代全部。
- 当前声明没有通用 `FocusScope`／`initialFocus`／`trapFocus`／`restoreFocus` 这些 API。先复用 NSH 语义边界与项目已有 ref／焦点策略，再按宿主补必要适配，不在方案代码里虚构 props。
- Desktop 与 TV 生成的 base 类型一致，不代表交互无需适配；TV 还要经过现有宿主 `TvRemote` 的方向、确认、返回与滑杆增减路径验证。

## 3. 现有基础与缺口

| 领域           | 当前已有                                                                        | 本方案处理                                                                          |
| -------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 主题／端型     | `theme.json` 浅深色与影院角色、`Product`、`tvUnit`                              | 保留配色和显式端型，补集中尺寸／文字／焦点规则                                      |
| 按钮／导航     | `Button`、`Controls`、`CardControls`、`CardRoot`                                | 保留行为，收敛外观和尺寸参数；已有来源焦点适配保留                                  |
| 输入／选择     | `SearchInput`、`SearchPicker`、`FilterChoices`、`EpisodeRange`、`CinemaSelect`  | 提取通用输入和选择基础，搜索／筛选继续作为组合；不复制下拉样式                      |
| 内容展示       | `Cover`、`PosterCard`、`ContinueCard`、`StoryFeature`、`ResultCard`             | 保留纯展示组合，封面失败不移除标题与动作                                            |
| 状态／布局     | `Surface`、`Notice`、`ContentArrival`、`Progress`                               | 分清容器和入场动效；空／加载／失败采用一致反馈                                      |
| 播放           | `CinemaButton`、`CinemaSlider`、`CinemaControls`、`EpisodePanel`／`EpisodeRail` | 影院是独立表面语境，共享行为和尺度规则；不把媒体会话放进组件                        |
| 设置／账号基础 | 尚无统一 Field、通用 Switch、Checkbox、确认对话框外观                           | 按已有实际页面需要补齐，不一次包装全部 NSH 控件                                     |
| 图标           | 原型和生产仍有手写路径                                                          | 后续按 [Lucide 规范](../../DESIGN.md#统一图标规范--2026-11-14) 迁移，当前不视为完成 |

`DownloadProgress` 是应用更新包的进度组件，不能据其名称恢复离线剧集下载需求。海报和选集等现有 UI 组件接收展示数据与回调，不依赖业务 store；出现剧目判断、请求或持久化时由 app 持有。

源码观察到 `player`／`search-picker`／`filter-choices` 从 `index.tsx` 回导基础定义；后续将端型、尺度、图标拆成小型内部模块，保持公共导出路径稳定，避免继续扩大入口循环。不是为此新建通用组件框架或插件系统。

## 4. 视觉基础

### 颜色与表面

沿用 `packages/ui/theme.json`，它仍是颜色唯一来源；本方案不直接修改主题。DESIGN 中的色表用于说明，不另成为第二份配置。

| 角色     | 浅色现值                      | 深色现值   | 使用规则                                       |
| -------- | ----------------------------- | ---------- | ---------------------------------------------- |
| 页面     | `#f8f8f7`                     | `#161816`  | 稳定背景，大面积留给内容                       |
| 普通表面 | `#ffffff`                     | `#20231f`  | 输入、菜单、对话框及必要分组；不把每行都包卡片 |
| 正文     | `#20211f`                     | `#f3f4ef`  | 标题与主要文本                                 |
| 次要文本 | `#686a64`                     | `#a6ada0`  | 必要元信息，避免用来承载关键状态               |
| 主动作   | `#c52e39`                     | `#f2777d`  | 当前区域的主要提交／观看动作，不给所有操作涂红 |
| 选中     | `accent`／`accent-foreground` | 同名 token | 浅底与清晰文本；不替代焦点框                   |
| 焦点     | `ring`                        | `ring`     | 稳定外轮廓，不放大或推挤邻居                   |
| 影院     | `cinema-*`                    | `cinema-*` | 深色画面与播控，即使页面为浅色也保持影院语境   |

菜单、选择列表、建议层和 Popover 统一弹层表面；禁止分别调一套灰色、圆角和阴影。需要弹层背景、遮罩或状态颜色时先补语义 token，确认浅深配对，再由组件引用。错误有文案与恢复动作；颜色不单独承载含义。对比度在组件样板的实际渲染中量测，不以色表代替通过证据。

### 尺度与排版

保留当前已经形成的页面尺度。下列为拟统一的档位，不是当前所有组件已达到的结果。TV 列为 **1920 宽设计参考单位**，必须经既有 `tvUnit()` 转换；不是直接当 dp/sp 使用，也不能只等比缩放就宣称观看距离或系统字号适配通过。

| 项目                   | Web／桌面                      | TV 参考值                                 |
| ---------------------- | ------------------------------ | ----------------------------------------- |
| 普通按钮、输入、Select | 最小高度 44，横向内距 16       | 输入与按钮同高 60，横向内距 24            |
| 紧凑次要操作           | 36，高密度次要区使用；同组一致 | 普通观看操作不使用桌面紧凑档              |
| 图标操作点击区         | 默认 44×44；图标 20            | 默认 60×60；图标 26                       |
| 选集按钮               | 详情 48，播放器面板 42         | 80；实际列数与字体放大协同检查            |
| 正文／操作             | 16；紧凑操作 14                | 正文／操作 22，重要选项可用 24            |
| 元信息                 | 14                             | 20                                        |
| 栏目／页面标题         | 24／32                         | 32／48；展示区标题沿用当前 48             |
| 标准圆角               | 12；紧凑影院控件 8             | 12                                        |
| 间距档位               | 4、8、12、16、24、32、40       | 8、12、16、24、32、48；按既有页面组合使用 |

字体使用系统 UI 字体，不为组件增加展示字体。进度、时间和榜位使用等宽数字特性。圆形仅用于头像、滑块拇指等确有含义的形态；标准按钮不统一改成胶囊。

颜色／圆角由主题承载；数值尺寸和字级在 UI 层集中定义，使用 NSH 已支持的 token／样式方式，不向 theme JSON 填造未支持的结构。组件档位一次决定高度、内距、字级、图标与间距，页面只选择档位。边框从 1 单位开始，焦点另画外轮廓并留空间，避免高亮改变尺寸或被裁切。

### 统一状态

| 状态              | 外观与行为                                                                    |
| ----------------- | ----------------------------------------------------------------------------- |
| 默认              | 中性底面、清晰标签；同组仅一个明确主动作                                      |
| hover             | 轻微底色变化；TV 不依赖 hover 揭示必要动作                                    |
| pressed           | 同色系加深／压暗，不缩放卡片，不移动布局                                      |
| focus             | 独立外轮廓，即时出现；可同时保留 selected                                     |
| selected／checked | 使用选中底色、文字及必要勾选标记；值来自调用方                                |
| disabled          | 不响应、不出现 hover／pressed；保持可理解的文案，不对整个区块统一淡出         |
| loading／pending  | 保留尺寸、上下文和数据；阻止重复提交但保留取消／返回路径，不把 pending 当成功 |
| invalid／error    | 文案指出问题，保留输入／结果，提供原位重试；不只给红框                        |

持续更新的播放时间、滚动位置和读取进度不触发整块入场动画。未知总时长／总数不画虚假比例或“共 N 项”。

## 5. 组件清单与 NSH 对应

先设计当前页面会消费的组件；“待补”表示 UI 包装尚未统一，不表示 NSH 没有这个能力。以下名称与接口为方案，不声明已经导出。

| 组件族                               | NSH 基础                                         | 统一设计                                                                           | 时机                         |
| ------------------------------------ | ------------------------------------------------ | ---------------------------------------------------------------------------------- | ---------------------------- |
| `Icon`                               | SVG 资源；必要渲染适配                           | Lucide，同一版本与语义映射，继承表面前景色                                         | 第一批，替换现有路径         |
| `Button`／`IconButton`               | `Button`；已有焦点适配                           | primary／default／quiet／destructive 四种视觉，md／sm 两档；图标操作强制可访问名称 | 第一批，兼容现有调用         |
| `TextInput`／`Field`                 | `Input`、`Text`、`View`                          | 标签、输入、可选帮助或错误；同档位输入与按钮对齐；搜索作为组合                     | 第一批，先搜索再账号         |
| `Select`／`ChoiceGroup`              | `Select`、`RadioGroup`／`ToggleGroup` 等合适语义 | 单选不冒充复选；统一触发器／列表；两端共用选择提交规则；承载表面差异需有实证理由   | 第一批，收敛三处现有 Select  |
| `Surface`／`Text` 角色               | `View`／`Text`                                   | 容器只负责表面与间距，文字采用有限角色；不为每个布局创建新壳                       | 第一批，保留现有名与用法     |
| `InlineStatus`／`Notice`／`Progress` | `Text`、`View`、`Progress`                       | 加载、空、失败、重试；原位反馈优先；进度需真实范围                                 | 第一批，先覆盖已有读取流程   |
| `Switch`／`Checkbox`                 | 同名 base 控件                                   | Switch 立即生效偏好，Checkbox 多选；轨道／拇指／勾选／禁用完整设计                 | 第二批，设置和记录管理使用时 |
| `Tabs`                               | `Tabs`／`Tab`                                    | 页面内分区，焦点和选中分离；导航组不伪装页面 Tabs                                  | 第二批，榜单／记录页使用时   |
| `Dialog`／`ConfirmDialog`            | `Dialog`；系统确认适用时 `AlertDialog`           | 标题、必要正文、明确动作；默认焦点不落危险提交；关闭恢复来源                       | 第二批，账号／确认流程       |
| `SidePanel`                          | `Sheet`                                          | 桌面与 TV 各自宽度，面板内独立滚动、关闭与返回明确；不是手机底部抽屉               | 第二批，复用选集面板         |
| `Menu`／`Popover`                    | 同名 base 控件                                   | 命令列表与自由内容区分；统一弹层表面和焦点边界                                     | 有实际菜单／锚点内容需求时   |
| `Tooltip`／`Toast`                   | 同名 base 控件与 `ToastStack`                    | 桌面图标提示、短反馈；TV 关键反馈可持续读取，不依赖悬停或瞬时提示                  | 对应真实需求出现时           |
| 海报／续播／搜索建议／选集／播控     | 以上基础组合＋`List`／`Scroll`                   | 沿用既有组件，值和回调受控；界面不制造内容、账号或媒体状态                         | 持续复用，最后按页迁移       |

Switch 的 track／thumb、Select 的 trigger／popup／item、Slider 的 track／range／thumb 都需明确样式。不能只写根容器后认为控件已经设计完成。业务集合默认使用 `List`，小而有界的面板可用 `Scroll`；虚拟行不得创建会串到其他剧目的业务状态。

## 6. 使用契约与边界

建议将当前 `primary`、`compact`、`episode` 等布尔或混合参数逐步收敛成有含义的外观和尺寸；选集／导航／影院仍可保留薄组合。避免一个按钮同时接收冲突的视觉参数。旧接口先兼容，按调用方迁移，不一次全仓替换。

下面是**目标公共 API 示意，尚未实现**，不是 NSH 自带 API：

```tsx
import { View } from 'nsh';
import { Button, TextInput } from '@hongguo/ui';

function QueryControls(props: {
  query: string;
  pending: boolean;
  onQueryChange: (value: string) => void;
  onSubmit: () => void;
}) {
  return (
    <View class="flex-row items-center gap-3">
      <TextInput
        label="搜索短剧、演员"
        value={props.query}
        onChange={props.onQueryChange}
        onSubmit={props.onSubmit}
      />
      <Button
        label="搜索"
        variant="primary"
        size="md"
        pending={props.pending}
        onPress={props.onSubmit}
      />
    </View>
  );
}
```

页面不传红色、圆角和自定义描边，UI 层将 `pending` 映射为真实可用状态；是否允许下一次查询／取消旧请求仍由 app 决定。原生值事件可在 UI 边界做一次明确适配，但不能把基础控件所有 props 逐一改名或吞掉 ref、焦点和取消能力。

| 状态／能力                                   | 所有者                                              |
| -------------------------------------------- | --------------------------------------------------- |
| 查询、表单值、选中剧目、请求错误、预约待确认 | app 页面／store                                     |
| 弹层展开、组内焦点、图片加载失败、动效阶段   | UI 局部；调用方需要控制时提供受控接口               |
| 导航来源、列表位置、返回焦点意图             | app 持有稳定身份，UI 提供 ref／焦点接口             |
| 持久设置、账号与历史                         | 按既有架构由 Rust／宿主管理；本方案不宣称迁移已完成 |
| seek 预览／提交                              | 控件报告 onChange／onCommit，app 决定媒体定位       |

明确 `Product` 端型，不用 Android OS 等同 TV；颜色不按 OS 分叉。复用现有 macOS `SelectFocus`、`CardControls` 来源停靠和控件移除交接，它们有宿主问题依据。替换为 base 控件前必须证明行为等价；不以“统一”为理由删掉这些适配。

## 7. 焦点、弹层与动效

- 桌面：Tab 进入区域，组内方向键按控件语义移动；NSH 0.5 Tabs 的方向键会触发 Tab.onPress 自动激活，不能统一改成确认后才选择。Select 的焦点预览与确认选值分开。Enter／Space 按控件语义执行；输入编辑与 IME 优先。明确的移除／关闭操作恢复附近有效焦点。
- TV：每个主要任务可用方向、确认、返回完成；控件及弹层打开后有可预测的初始焦点。左右不抢普通输入的光标，上下离开编辑区；正在 IME 组合时不抢键。
- 返回：先最上层弹层／选集，再播放控制层／定位预览，再页面来源；不要多个 key handler 同时消费返回。隐藏的控件、离场动画和非活动页面不能接收焦点。
- 弹层：使用语义 Dialog／Sheet／Select／Popover 的边界；搜索建议继续为非模态，输入焦点可保留。禁止拿绝对定位 View 重新实现通用弹层行为；现有 Overlay 组合若要迁移，先验证建议键盘与关闭行为。

| 状态变化                       | 拟沿用动效                                        | 减少动态效果                   |
| ------------------------------ | ------------------------------------------------- | ------------------------------ |
| hover／pressed／selected 换色  | `fast=100ms` 颜色变化；focus 即时                 | 即时换色                       |
| 锚点建议／菜单显隐             | 100ms 淡入淡出，焦点在出现时同步安排              | 即时                           |
| Dialog／Sheet／影院控制层      | 180ms；面板位移只用于表达进入方向，不叠加页面编舞 | 无位移、即时或按宿主无动画选项 |
| 页面内容首次出现               | 既有 `base=180ms`、最多 8 单位；一次且按内容身份  | 无位移                         |
| 列表追加、筛选、进度、续播文字 | 原位即时更新；保留旧结果与焦点                    | 相同                           |

不添加提示音、装饰循环、海报缩放和逐条错峰动画。`Surface` 后续应只负责静态容器，入场统一由 `ContentArrival` 等显式组合选择；当前两者减少动态效果处理并不一致，属于迁移检查项。影院显隐保留迟到回调防护，不能让已隐藏控件重新出现。

## 8. 样板与实施顺序

本轮先交付 [浏览器组件设计样板](../../design/prototype/components/index.html) 与 [设计交接](component-design.md)，用于确认视觉与交互，独立于原产品原型；它不是 NSH 实现。产品实施继续暂停。设计确认后的**原生组件验收页**才在当前 NSH workspace 内以显式开发／测试入口装配，独立于默认产品路由，不另建 React／Storybook 工程。

样板按任务分三组：

1. **找剧**：输入＋搜索按钮＋Select／筛选＋结果行，覆盖读取中、无结果、续页失败与键盘返回。
2. **设置／确认**：Field＋Switch＋Checkbox＋确认弹层，覆盖错误、只读／禁用、取消与保存待确认；样例只模拟 UI 状态，不调用账号或写设置。
3. **观看**：深色影院按钮＋进度／音量滑杆＋倍速 Select＋选集面板，覆盖隐藏、定位确认／取消、末集、真实可用清晰度为空时的反馈。

每组展示普通、hover、pressed、focus、selected、disabled、pending、error 的适用状态。鼠标 hover 不冒充 TV 状态。样板数据明确为演示，不作为业务协议凭证。

实施分三步，生产实施当前均未开始；浏览器设计样板已补齐八组，尚未迁入 NSH：

| 步骤           | 交付                                                                                          | 退出条件                                                                      |
| -------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| A · 基础定标   | 现有组件清单、集中尺寸／文字／状态规则、Lucide、Button／Input／Select／状态展示，先做找剧样板 | 桌面／TV 深浅可见样板成立，尺寸和焦点得到确认；现有路径和媒体逻辑不被连带改写 |
| B · 表单与弹层 | 设置／确认与观看样板，补必要 Switch／Checkbox／Tabs／Dialog，统一弹层表面                     | 键盘／遥控模型、返回与来源焦点、输入法、减少动态效果有证据                    |
| C · 逐页迁移   | 按找剧→详情／选集→播放器→记录／账号／设置顺序消费共享组件，清理已无调用的旧变体               | 每页对照修订设计；旧接口消费完才移除；对应工程与宿主回归通过                  |

每步评审组件样板与实际页面，不等到全站替换完才看效果。底层渲染方式不会成为给用户解释的标签；用户只看到一致的控件、明确的下一步和可靠恢复。

## 9. 验证与交接

- 工程：实际实施需执行对应端 check **和** build；行为变化测焦点、受控状态、重复动作、输入法和取消／迟到回调。批次运行项目要求的 verify；新依赖按 security 门禁执行，不降低既有策略。
- 视觉：Web／macOS 在已支持桌面窗口观察浅深两色；TV 以 1920 参考画面、实际 density 和系统字号 1.3 检查。圆角、字号、间距、对齐、颜色、hover／pressed、状态、动效逐项留证。
- 可访问性：操作名称、分组、焦点顺序、控件值、错误描述及关键反馈可读取；普通文字对比度目标 4.5:1、大文字及必要控件边界 3:1；不能只以静态截图认定读屏通过。
- 限制：浏览器原型、NSH headless、模拟器和物理 TV／遥控／硬解证据分别记录，未完成的平台明确留空。本方案不代表 API 已封装、图标已迁移或任何宿主验收已完成。
- 开发／Agent：公共出口保持 `@hongguo/ui`，使用有限变体、类型化图标名与稳定 testID；内部按实际职责拆文件，示例标明可执行或草案；避免页面复制样式、全局布尔组合及隐式宿主分支。

当前交付为本方案、独立浏览器组件设计样板及演进规划；生产组件、主题与依赖未修改，未提交／推送。下一阶段先评审 A 的组件样板，再决定组件 API 和视觉细节是否进入规范。
