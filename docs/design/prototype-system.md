## 视觉映射

沿用根目录 DESIGN.md 的视觉身份，未修改生产主题、组件或设计系统快照。原型的 CSS 不是生产主题的第二编辑源；移植到 NSH 时仍由 `packages/ui/theme.json`、共享 UI 控件与动效管理视觉值。

| 原型角色   | 浅色      | 深色      |
| ---------- | --------- | --------- |
| background | `#f8f8f7` | `#161816` |
| foreground | `#20211f` | `#f3f4ef` |
| card       | `#ffffff` | `#20231f` |
| primary    | `#c52e39` | `#f2777d` |
| accent     | `#fbe8e9` | `#42282a` |
| ring       | `#b42130` | `#ffa6ab` |

应用内颜色引用语义变量；播放器另有 cinema、on-cinema、cinema-muted、cinema-control、scrim 角色。渐变只用于封面和播控的文字可读性。未新增装饰投影、渐变文字或标题上方的装饰标签。

桌面正文为 14–16px、内容标题 18–24px、页面标题 26–32px；TV 正文与操作为 20–24px、栏目标题 28px、页面标题 44px、内容展示标题 48px。以上是浏览器原型的 CSS 像素，尚未映射或验证为 Android TV dp/sp。主控件与海报使用 12px 圆角，头像为圆形；进度条、开关、评审工具和旧辅助组件保留局部几何。TV 主要操作至少 60px 高；窄窗口的媒体图标按钮为 44px 点击区。

这些字体尺度与局部圆角是原型提案，不是根目录 DESIGN.md 已接受的生产标准。检测器的相应建议保留在评审记录中，不通过添加全局忽略或修改生产规范使其消失。

## 焦点和播控

- 选中状态用底色／文字表达，TV 当前焦点用独立外轮廓表达；焦点不放大卡片或挤动布局。
- 页面返回保存来源控件、滚动位置及选集区间；弹层关闭恢复触发控件。主导航与内容区分别可达。
- TV 播放器先收起最上层面板，再处理进度预览、控制层和页面返回。控制层隐藏时，确认键唤起；左右方向键发起定位预览，确认提交、返回取消。
- 控制层显示时，进度滑杆可直接调整；下一集受已上线集数限制。媒体播放键仅模拟状态，不播放音视频。
- TV 搜索输入框可用下方向键离开；选项内上下调整、左右或确认离开。文本区在末尾可向下离开。正式 NSH 实现需按宿主输入法和原生选项控件重新验证。
- TV 修复约定：普通单行输入上下键转移焦点，左右键保留光标编辑；输入法组合期间不拦截按键。只读演示号码不进入焦点路径。影院播控／定位键仅归播放页，刷剧浏览页遵循普通导航与一次返回。
- 同一剧目的同一 TV 评论面板原位更新时保留阅读滚动和来源焦点。开始观看／指定集从零开始，续播显式读取该剧保存的集数与位置，不继承其他剧目的时间。
- TV 找剧将类型、题材、排序收敛为一排具名选择框；结果先于排行榜、上新日历、刷剧等栏目入口。筛选与排序语义由桌面和 TV 共用同一派生函数。

TV 本轮动效清单：筛选改变、进度初始化、评论内容及阅读位置恢复沿用即时状态更新；不新增动画。选择框沿用原生选项交互与现有焦点外轮廓，影院控制层仍沿用既有透明度过渡及减少动态效果约定。实现后的视觉／宿主验收单独记录。

- 标签组采用 roving tabindex，标签和内容面板关联；对话框使用原生 dialog 的模态焦点边界。
- 桌面收藏、点赞、追更和预约使用统一的选中底色与 `aria-pressed`；评论点赞同步表达选中状态。返回入口采用轻量文字操作，与播放主动作区分。
- 桌面右栏同一剧目、同一上下文面板内的操作保留阅读滚动位置与来源焦点；切换剧目、面板、季或集数区间时重新开始对应内容。同一评论弹层在未关闭时原位更新，保留滚动和焦点。
- 桌面全屏保留播放器宿主及画面节点，播控动作只更新内部状态；画面占满播控以外的高度，保留等比显示。播控内提供选集、评论与退出全屏入口。弹层焦点按当前面板查找，避免落到背景右栏的同名输入框。
- 评论、草稿、回复对象和点赞状态按剧目隔离；返回同一剧目恢复该剧草稿。找剧排序只作用于筛选后的列表，重复选择保持顺序，综合恢复样例基准，不改变首页或榜单。

本次未新增动效：全屏切换由浏览器负责，播控状态原位更新，选集与评论沿用既有面板及减少动态效果约定。全屏修复仅完成部分宿主观察，剩余验证按用户要求停止，详见 [desktop-review-fixes.md](desktop-review-fixes.md)。

## 原型状态与工程

`app.js` 管演示模型、动作、路由、返回和焦点；`desktop.js`／`desktop.css` 与 `tv.js`／`tv.css` 分别管页面和组合。`styles.css` 管共享视觉基础和辅助页面。两个宿主壳同时只有一个显示，隐藏端的内容被清空，避免重复控件和不可见焦点。

未引入 React、Vite 或 npm UI 依赖。使用项目已有 Oxfmt 检查原型格式，JavaScript 通过语法检查。设计稿本地启动：

```sh
node design/prototype/serve.mjs
```

评论隔离、两端筛选排序与续播、TV 输入／返回、弹层焦点和阅读滚动的自动回归：`node --test design/prototype/prototype.test.mjs`。

访问 `http://127.0.0.1:4178/`；TV 为 `http://127.0.0.1:4178/?platform=tv`。顶部评审工具提供页面地图、主题、平台与正常／加载／空／失败状态。

原型内剧目、封面、统计、账号与互动均为样例；数据只在内存保留，刷新复原。登录、评论、预约、同步、下载、支付及更新均不连接真实服务；二维码不可扫描。点击模拟播放才将新剧加入演示历史，进入静态播放器本身不作为实际观看。

## 交付与未验证

页面地图覆盖完整目标功能，允许审阅流程和关键状态；这不表示原客户端的每条接口、后台时序、同步隔离、内容审核或任务执行已实现。支持／应用入口保留明确的未配置状态，不编造支付信息和应用来源。

浏览器已检查桌面、390px 窄窗口及 1920×1080 TV 的主要页面和关键交互。截图、检查结果及一次检测器报告保存在 `.impeccable/review/`，结论见 [redesign-review.md](redesign-review.md)。原型未修改生产 NSH／Rust，也没有运行生产 `pnpm verify` 或宣称其通过。

此前桌面细节打磨在 1280×900、1440×1000、1920×1080 浏览器视口核对，记录见 [desktop-polish-review.md](desktop-polish-review.md)。用户随后要求独立评审并修复 TV 原型；本轮行为回归与视觉未验收项见 [tv-review-fixes.md](tv-review-fixes.md)，不沿用旧截图宣称新布局已通过。

真实 TV 遥控器与输入法、观看距离、系统字体缩放、辅助技术、媒体解码、后台恢复、独立安装包和系统首页频道尚待真实 NSH 宿主验收。浏览器截图和方向键模拟不能替代这些证据。
