# 高频组件预先设计与演进

2026-11-14。补充现有组件设计；随后已授权基础组件实施。本文固定高频用途与准入边界，实际公共导出和组合归属见 [实施验收](component-implementation.md)，不据此新增业务能力。

## 分层与准入

组件分为布局配方、通用控件、业务组合。布局直接组合 NSH `View`／`Text`，不为 Stack／Inline／Grid 另造布局框架；通用控件进入 `packages/ui`；数据读取、筛选意义、账号和播放器会话留在 `packages/app`。每个候选必须说明用途、状态、焦点路径和 NSH 承接方式。

“已设计”仅表示浏览器样板，不等于已有生产导出。原有八组及九类组合覆盖见 [覆盖清单](component-coverage-audit.md)。本轮新增样板仍加入原分组，不增加产品入口。

## 本轮提前设计

| 组件／配方              | 高频用途                       | 设计与交互契约                                                                                                       | NSH 承接                                                                                            | 样板位置             |
| ----------------------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | -------------------- |
| Stack／Inline／Grid     | 标题与内容、元信息、同组动作   | 集中间距档位；Inline 可换行；Grid 内容最小宽度为零；布局本身不获取焦点                                               | `View` 的布局与既有 token，不新增改名包装                                                           | 基础：布局配方       |
| ExpandableText          | 剧情简介、来源说明             | 短文直接显示；长文折叠为摘要，按钮明确“展开／收起”；展开不替换原文、不弹新层；触发器保留焦点                         | `Text`＋`Button`＋`Collapsible`；截断／测量以实际 NSH 类型与宿主验证                                | 基础：文本展开       |
| Disclosure／Accordion   | 设置分组、来源细节             | 独立展开值；可同时打开多个；标题、展开状态、受控区域关联；禁用分组不可操作；折叠后内容不进入焦点顺序                 | `Accordion`／`AccordionItem`／`AccordionHeader`／`AccordionTrigger`／`AccordionPanel`，不另建状态机 | 基础：折叠分组       |
| Link                    | 官方来源、项目源码、在线说明   | 有真实目标才可激活；外部资源使用链接，应用内动作仍用 Button；目标完整可读；不可用链接无焦点、不伪造 href             | `nsh/base` 的 `Link`，由宿主打开；TV 无浏览器能力时使用明确不可用状态                               | 基础：资源链接       |
| KeyHint／InputHint      | 搜索提交、弹层返回、定位调整   | 只解释已存在的操作，不自行注册快捷键；桌面显示按键，TV 显示“确认／返回”；无焦点、不抢操作                            | `Text`／展示布局；实际命令由所属控件或 app 注册                                                     | 基础：输入提示       |
| RemovableChipGroup      | 已选筛选条件                   | 显示条件值和逐项移除名；清空全部为独立动作；移除后焦点交给下一项、上一项或空态恢复入口；不把 tag 当选择器            | 已有 Button／Icon；由调用方提供稳定 ID 和 change，不新增 base primitive                             | 按钮与选择：已选条件 |
| ActionBar／Toolbar      | 列表刷新、排序、管理、批量动作 | 主要操作常显，次要命令由已有 Menu 承载；同组等高；空间不足换行，不隐藏唯一入口；菜单关闭恢复来源；等待时阻止重复动作 | `Toolbar`／`ToolbarGroup`／`ToolbarSeparator` 与既有 Button／Menu；TV 输入适配在统一边界            | 按钮与选择：操作栏   |
| FieldGroup／FormSection | 一组相关设置、错误关联         | 组标题、字段标签各出现一次；组级说明与错误有归属；只读、禁用、立即偏好和提交表单不混用；重用既有 Field               | 布局＋已有字段；浏览器用 fieldset／legend，NSH 用分组语义与实际声明，不杜撰 Fieldset API            | 输入与表单：表单分组 |

共用端型档位：桌面普通交互目标 44、TV 60；TV 不靠 hover、提示气泡或缩放揭示动作。Disclosure、文本展开、条件移除与表单语义两端一致。Toolbar 的桌面组内键盘与 TV 空间导航属于输入差异，不复制业务控制器。

Button／IconButton、Field／Input／Search、Select、ChoiceGroup、Tabs、Checkbox、Switch、Slider、Menu／Popover／Tooltip、Dialog／Sheet、Notice／Toast、Empty／Skeleton／Progress、Avatar／Badge／Separator、Cover／Card／ResultRow、Collection／Pagination、日期条、季选择、设置行、账号输入、快照表、预约与提醒、记录管理和影院控件已进入样板。新增需求先查这些组合，不再为名称相近的功能建立第二套。

## 预留候选及触发条件

| 候选                                | 何时进入详细设计                                          | 预先固定的边界                                                                           |
| ----------------------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| CommandItem／ContextMenu            | 同一内容出现至少两处一致命令，且常规菜单不能满足调用位置  | 与现有 Menu 共用命令定义、禁用状态和确认；TV 始终有可见的更多入口，不依赖右键或长按      |
| StatusBanner／CapabilityNotice      | 多个页面需要跨区持续提示同一实际宿主／网络状态            | 沿用 Notice 的状态角色；关键结果持久可见；能力由宿主报告，不能根据平台名称猜测           |
| SearchHistory／SuggestionSection    | Rust 提供明确的本地查询历史契约，并确认保存范围与清除语义 | 复用现有 SearchPicker；不读旧客户端数据，不假装热门词或远端推荐                          |
| CopyValue／CopyFeedback             | 出现用户需要复制的真实来源／诊断字段，且宿主有剪贴板能力  | 只复制用户指定值，反馈成功以实际结果为准；失败保留可选文本，不暴露凭据                   |
| WindowTitlebar／FocusReturnBoundary | 开始原生组件迁移或窗口结构调整                            | 优先沿用现有宿主、NavStack、来源焦点与移除交接；不在页面里重复造窗口或焦点系统           |
| 大集合的回收／定位状态样板          | 生产集合进入可增长数据和跨屏跳转验收                      | NSH `List` 虚拟化；稳定 ID、回收无串值、追加保留锚点。现有有界浏览器集合不能证明性能通过 |

以上先记用途和准入，不制作空壳生产组件。可调整大小的分栏、完整日期选择、树、命令面板、拖拽排序、富文本、上传、图表不作为当前高频基础；需求改变后再评估。评论、弹幕、剧评、点赞和离线剧集队列继续排除。

SearchHistory 已有页面原型演示；这里的触发条件针对生产接入与公共接口，不表示缺少浏览器设计。

## 后续交付门槛

每次添加或修改组件，同时更新用途／状态清单、桌面／TV 设计样板、稳定测试定位与消费示例。默认先复用；新组件有第二个真实用途或明确不同语义才抽公共接口。外观不接受任意颜色、圆角或字号覆盖，避免页面和 Agent 发明变体。

本轮仅浏览器设计，验证结果追加到 [组件评审](component-review.md)。原生落地必须对照各端 `.nsh/types/`，完成 check 和 build，再检查可见宿主、遥控／输入法、大字号与读屏；不会将浏览器键盘模拟视作真机凭证。

本轮独立复审结论为 **ship**，范围限八类新增浏览器设计；21 张主题／平台／边界状态截图复核通过。原型既有 24 项回归、语法与定向格式检查通过；新模块的交互证据来自浏览器操作，非完整自动化覆盖。具体证据与限制见组件评审的“高频基础预先设计独立复审”。
