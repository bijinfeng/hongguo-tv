# 基础组件候选与准入

公共视觉／交互归[DESIGN](../../DESIGN.md)，实际API归[UI包](../../packages/ui/README.md)，已有实现与组合归[单一覆盖矩阵](./component-implementation.md)。本页只维护尚未触发的候选，不再描述已实现组件的重复契约。

## 准入条件

先证明真实用途、必要状态、焦点／返回路径和NSH承接；有第二处相同需求或明确不同语义时再形成公共封装。布局用NSH View，已有控件能组合就复用，不制作未来空导出、不因样板反向创造业务。

| 候选                           | 触发条件                                           | 必须保持的边界                                                 |
| ------------------------------ | -------------------------------------------------- | -------------------------------------------------------------- |
| CommandItem／ContextMenu       | 多处相同命令，常规Menu无法满足调用位置             | 共用命令／禁用／确认语义，TV保留可见更多入口，不依赖右键或长按 |
| StatusBanner／CapabilityNotice | 多页需要持续表达同一实际宿主／网络状态             | 复用Notice角色；能力由宿主报告，不能按平台名称猜测             |
| CopyValue／CopyFeedback        | 用户确实需要复制真实来源／诊断值，宿主有剪贴板能力 | 实际成功才反馈，失败保留可选文本，不复制凭据                   |

SearchHistory／输入联想已有Rust与app实现；日期／选季／榜位／快照表已有公共控件；窗口／焦点恢复和List虚拟化已有宿主及生产承接，不再列成“尚未有能力”的候选。长列表回收／定位、IME和焦点等是实际使用验收事项，不靠新增同名包装解决。

完整日期选择、树、命令面板、拖拽、富文本、上传、图表或可调分栏目前没有新增公共API的需求依据；需求触发后再评估，不计MVP缺口。产品排除范围以PRODUCT为准。

[早期高频设计与候选记录](../history/2026-11-15/design/component-roadmap.md)保留当时用途、触发条件和状态；本页不重复维护实现／验收进度。
