# 设计真实性审查 · 2026-11-14

当前结论：先修订设计，产品实施保持暂停。观看流程收敛为找剧、详情、播放、选集、续播、收藏、追更与预约；评论、回复、弹幕、剧评、点赞及相关入口／设置由用户主动排除，不再作为缺失功能补回。

## 审查依据与边界

行为依据为 `upstream.lock.json` 固定的 [aston314/hongguo-tv](https://github.com/aston314/hongguo-tv/tree/de9712bf358dcbdf8a188e26cba711e3e5354e8a) 提交；原型是 `design/prototype`，浏览器审阅入口为 `http://127.0.0.1:4178/`。剧目、封面、账号和指标均明确标注为演示样例，不是线上数据。

本次覆盖设计稿的业务真实性、桌面／TV 原型布局与关键交互；未做官方红果 App 的逐像素对照。未连接真实账号、扫码、预约或媒体；浏览器方向键不等于实体遥控、NSH 宿主或物理 TV 验收。此前实现半成品保持冻结，不将本轮设计修订当作生产功能完成。

## 审阅流程与健康状况

1. **首页 → 找剧／搜索 → 结果**：主要导航与续播入口保留；分类和关键词语义分开，筛选与结果排在热搜等辅助区之前；追加失败保留已有结果。列表焦点、查询隔离有原型回归。样例 schema 不能成为新协议。
2. **结果 → 详情 → 演员／季／选集**：演员与剧目身份分开；系列条目区分可播与待上线，不能拿预约身份播放。演员与相关作品依响应出现，不用全站其他剧填空。
3. **选集 → 播放 → 返回／续播**：桌面保留视频与选集栏，TV 保留独立影院控制层；社交面板全部退出。TV 方向键与弹层返回恢复焦点已作浏览器观察，真实遥控／输入法另验。
4. **新剧／日历 → 预约 → 更新提醒**：推荐与日期数据源分开；预约提交不伪装确认，提醒是刷新发现后的应用内记录，不承诺关闭应用后准时推送。已读提醒保留，不直接删记录。
5. **账号 → 合并／记录 → 设置**：登录失败／取消回原任务，写操作不自动重放；历史、收藏和统计分清对象与影响范围。默认倍速与设置回显在浏览器核对。

修订后核心观看层级清晰，未额外增加装饰动效；原有弹层与控制层过渡保留减少动态效果约定。辅助功能仍有边界：浏览器焦点和标签回归不能证明屏幕阅读器、系统字体放大、TV 观看距离或完整 WCAG 合规。
