# 新剧与上新日历

源码位于主工作区的 `packages/app/src/calendar.ts`、`pages/Calendar.tsx`；三端入口只装配共享页面。单日期控件由 `@hongguo/ui` 的 `DateChoice` 提供，桌面与 TV 共享受控值、确认选择、焦点和日期校验，尺寸随根 `Product.Provider` 变化。临时构建缓存和 ignored 验收宿主不是产品源码。

## 浏览与数据边界

- 默认打开上新日历，只展示服务端给出的真实日期。新剧模式独立保留全部／男生／女生选择；日历没有伪造的人群或题材筛选。
- 首次默认日期读取省略日期与预约游标；取得默认日期后，续页固定到该日期，避免跨日混入另一页。已上线与未上线使用不同身份，双游标原样继续，空但前进的页可以继续浏览，失败在原路径重试。
- 模式、日期和人群独立缓存；离页、后台和卸载取消所属请求并隔离迟到结果。窗口仍可见的 inactive 状态保留读取；真正 background 才取消。
- 已上线卡片进入既有详情。未上线卡片只显示公开安排，预约 ID 不当作短剧 ID，不发播放、详情、预约或历史写入，也不模拟预约成功。
- 安排占用列表原有内容区，隐藏列表同时退出交互和无障碍树。收起按钮常驻，正文可滚动；收起或返回恢复卡片来源。日期／模式切换关闭旧安排。保留的列表与虚拟化锚点避免重新取页，较新的导航优先于异步焦点恢复。

## 输入与布局

桌面保留四列列表，TV 使用单行海报；日期条按实际内容高度留足焦点空间。方向键在日期组中只移动焦点，确认才选择。详情返回先恢复缓存视口；来源未挂载或不完整可见时才居中定位到来源行，不把旧行的偏移套到另一行。滚动后重新测量再聚焦；至多主动重试一次，未收敛时等待布局／ref 通知，较新输入会撤销旧恢复。

外焦点空间属于每个虚拟行的实际几何，不能只在整个列表首尾留空。桌面每行上下各 8，卡片预算再计入原生聚焦显露的余量，扣除列表高度总计 32；TV 每行左右各 8，内部海报宽 260，行宽 276，外间隔 12 与两侧留白合成 28 的海报间隔。TV 的交叉轴上下各 8，卡片预算扣除 16。共享 PosterCollection 使用同一布局规则；空间充足时仍保留常规封面比例。

安排正文有命名 region。桌面在收起按钮或正文区域聚焦时可用上下／Page Up／Page Down 滚动，Home／End 到首尾，确认收起、Escape 先关闭安排。TV 由原生输入适配将命名的可滚动区域纳入遥控导航，上下先阅读至边缘，再离开区域；返回先关闭安排。正文同时声明 `role="region"` 与 `focus-region-*` 标记，旧 API 不能仅凭名称推断阅读区域；公开标记契约见 ENGINEERING。共用正文和关闭语义，不复制页面或业务控制器。

## 状态与动效清单

| 状态变化                                  | 工具与共享 token                                        | 减少动态效果       |
| ----------------------------------------- | ------------------------------------------------------- | ------------------ |
| 日期／模式／卡片 hover、pressed、selected | 共享控件的 fast 颜色／透明度反馈；焦点独立              | 即时颜色，保留焦点 |
| 首批内容、安排正文、错误出现              | ContentArrival／Notice；entrance 180ms、easeOut、距离 8 | 即时可见，无位移   |
| 追加、回收、日期／模式缓存返回            | 稳定列表布局与锚点，无逐卡入场                          | 相同               |
| 安排收起、返回、正文阅读                  | 即时恢复来源、非动画滚动；较新输入撤销旧恢复            | 相同               |
| 详情进入和返回                            | 既有 NavStack 与来源守卫                                | 沿用现有平台策略   |
| 加载与重试                                | 可见等待文案、pending 禁用重复请求                      | 相同，不虚构进度   |

无界面断言不能验证动效、焦点环或布局。实际宿主的检查结果及未验项记入根 `VALIDATION.md`，不以静态终态截图证明逐帧表现。

## 复现

```sh
node tooling/src/calendar-host.mjs headless
node tooling/src/calendar-host.mjs headless --product tv
node tooling/src/calendar-host.mjs web
node tooling/src/calendar-web-terminal.mjs
node tooling/src/calendar-host.mjs macos --foreground
node tooling/src/calendar-tv-remote.mjs run
pnpm verify
```

宿主用例使用合成只读数据，真实图片来自本地原型资源。支持 `--filter <用例子串>` 缩小桌面宿主检查。Android 遥控脚本使用独立安装 ID、项目原生输入源码和共享 TSX；退出恢复设备设置与前台，卸载本次验收包，核对既有生产 APK 摘要。其源码和命令在主仓，派生工程／截图在 ignored 目录。

Web 延迟终页另用真实 HTTP 夹具运行八组独立场景，检查精确重试、双游标、请求次数及只读边界。NSH 0.5.0 的 Web 测试网络 stub 在空闲引擎收到延迟回复时缺少唤醒，旧延迟 stub 失败日志保留；常规 Web stub 用例只检查即时终页，不替代上述真实 HTTP 延迟验收，也不为测试修改 NSH runtime。2026-11-17 升级 NSH 0.5.1 后未重验该取舍：工作区并行的 UI 改动使这些宿主用例在收尾只读断言上多出一次 `/api/v1/category` 请求而失败（headless 与 web 同样复现），无法据此判断延迟 stub 的唤醒问题是否已修复。

`calendar-tv-host.mjs` 的标准 NSH 开发宿主只用于渲染和触摸观察；其普通 View 的 `ref.focus()` 不等同于项目 TV 原生输入适配，不能作为遥控来源恢复通过的证据。上述夹具／验收包也不能证明正式 APK、物理遥控、读屏、真实账号预约、媒体解码或线上数据完整遍历。

## 独立审查

功能审查覆盖控制器所有权、双游标、重试路径、公告身份和宿主返回。审查指出来源恢复在虚拟行未收敛时过早聚焦；现已改为滚动后测量、一次主动复测及布局通知驱动的等待，较新的输入始终优先。

视觉审查发现 1180 桌面窗口中卡片文字与外焦点裁切，先在共享 PosterCard 按实际文字高度收缩封面，再把安全区纳入虚拟行及原生显露预算。最终两尺寸浅深的来源返回与模式缓存八张截图完成独立复核；TV 浅深／1.3 字号的日期、公告和长文阅读也完成实看。圆角、字级、间距、对齐、主题配对和可见状态按该范围检查；静图不证明逐帧动效、精确锚点相等或读屏。实际命令、数量、保留的失败及证据见根 VALIDATION 的本批记录。
